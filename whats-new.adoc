=== AI Data Engine



==== AI Data Engine 1.3

AI Data Engine 是一項中繼資料智慧服務，透過 NetApp Console 代管，可掃描您連接的系統、建立中繼資料目錄，並為您提供可見度與工具，以最佳化儲存設備並大規模治理資料。您可以將 AI Data Engine 部署為 https://docs.netapp.com/us-en/ai-data-engine/deploy/deployment-overview.html["AIDE 單一節點部署"^]，或者如果您的環境需要以 Kubernetes 為基礎的大規模高可用度，則可部署為 AIDE 多節點部署。

AI Data Engine 1.3 是第一個正式發布（GA）的版本。

.部署並連接您的資料
https://docs.netapp.com/us-en/ai-data-engine/deploy/deployment-overview.html["以您的環境所需的規模進行部署"^]:: 選擇 AIDE 單一節點部署可在單一虛擬機器上快速啟動，或選擇 AIDE 多節點部署在您自己的 Kubernetes 叢集上以實現高可用度和更大規模。如果您的環境需要 Proxy 才能存取網際網路， https://docs.netapp.com/us-en/ai-data-engine/deploy/configure-proxy.html["了解 AIDE 的 Proxy"^] 請使用 Proxy 部署。
https://docs.netapp.com/us-en/ai-data-engine/data-sources/connect-data-source.html["將您的資料納入範圍"^]:: 連接檔案共用、資料庫伺服器和 StorageGRID 系統，並選擇要掃描的資料資源。
https://docs.netapp.com/us-en/ai-data-engine/administer/monitor-deployment-health.html["保持掃描健全狀況良好"^]:: 監控部署的健全狀況，找出可能中斷掃描的問題，並收集解決這些問題所需的詳細資訊。


.最佳化儲存設備並調查您的資料
https://docs.netapp.com/us-en/ai-data-engine/investigate/understand-dashboard.html["恢復儲存容量"^]:: 根據您設定的閾值，識別已連線系統中的冷資料、陳舊資料和複製資料，並查看哪些系統和資料擁有者擁有最高濃度的此類資料。
https://docs.netapp.com/us-en/ai-data-engine/administer/configure-settings.html["為您的組織定義冷資料和過時資料"^]:: 設定閾值，以決定哪些資料被歸類為冷資料或過時資料，以符合您的資料保留原則。
https://docs.netapp.com/us-en/ai-data-engine/investigate/understand-dashboard.html["確定資料相關聯絡人"^]:: 從儀表板中識別哪些資料擁有者持有最集中的冷資料、過時資料或複製資料。然後在調查檢視中依擁有者或群組進行篩選，以審查結果並找出要聯絡的對象。
https://docs.netapp.com/us-en/ai-data-engine/investigate/investigate-data.html["降低成本和風險"^]:: 按存取時間、修改日期、建立日期、檔案大小、複製狀態和其他條件篩選所有已連接系統中的檔案，以尋找符合組織資料管理員目標的檔案。可以直接根據結果採取行動，也可以將篩選條件儲存為原則。
https://docs.netapp.com/us-en/ai-data-engine/investigate/investigate-data.html["消除複製資料"^]:: 尋找在您連線的系統中具有複製副本的檔案。依「複製」屬性或檔案雜湊進行篩選以審查複製群組，然後清理複製副本。
https://docs.netapp.com/us-en/ai-data-engine/investigate/investigate-directories.html["尋找存取風險"^]:: 識別具有開啟權限的目錄，以便您可以優先對這些目錄進行權限審查。
https://docs.netapp.com/us-en/ai-data-engine/investigate/investigate-structured.html["調查結構化資料"^]:: 尋找已連接的資料庫伺服器上過大或未使用的資料庫資料表。

.受監管的 AI 存取
https://docs.netapp.com/us-en/ai-data-engine/mcp/learn-about-mcp.html["賦予 AI 用戶端對您中繼資料的受治理存取"^]:: 透過模型上下文協定（MCP）將 Claude Code、Claude Desktop、Cursor 或 OpenCode 連接至 AI Data Engine。啟用 AI 用戶端可搜尋的集合，並使用 Microsoft Entra ID 範圍來控制誰可以搜尋每個集合。AI 用戶端可以搜尋中繼資料和標記檔案。


.行政
https://docs.netapp.com/us-en/ai-data-engine/administer/manage-users-roles.html["指派管理員與檢視者角色"^]:: 透過將 AI Data Engine 系統管理員或檢視者角色指派給組織中的使用者，來控制誰可以調查資料並採取行動。

=== 備份和復原



==== Kubernetes 工作負載增強功能

在此版本中，NetApp Backup and Recovery 針對 Kubernetes 工作負載引入了以下增強功能：

* *Trident Protect 26.10*：此版本包含 Trident Protect 26.10。
* *ontap-nas-economy 和 ontap-san-economy 驅動程式支援*：現在您可以保護由 NetApp Trident `ontap-nas-economy` 驅動程式（Qtree）和 `ontap-san-economy` 驅動程式（LUN）配置的持續性 Volume 宣告（PVC）。使用經濟型驅動程式保護 PVC 時，整個底層 FlexVol 或 LUN 都會受到保護。您可以從這些備份中還原個別的 PVC。
* *Kubernetes 感知警告*：警告現在每個 Kubernetes 應用程式發送一次，而不是每個 Volume 發送一次。
* *Volume 群組快照支援*：現在您可以在定義 Kubernetes 應用程式時建立 Volume 群組。Volume 群組可讓您將多個 Volume 一起快照為損毀狀況一致的集合，確保群組內所有 Volume 的資料一致性。
* *S3 相容物件儲存支援*：您現在可以透過新增備份目標認證資料和設定保護原則，將 Kubernetes 應用程式資源和資料備份到 S3 相容物件儲存。


有關保護 Kubernetes 工作負載的詳細資訊，請參閱 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["了解如何使用 NetApp Backup and Recovery 保護 Kubernetes 工作負載"^]。



==== ONTAP Volumes 工作負載增強功能

在此版本中，NetApp Backup and Recovery 針對 ONTAP Volumes 工作負載引入了下列增強功能：

* *保護報告*：NetApp Backup and Recovery 現在支援建立和下載 ONTAP Volumes 工作負載的擴充報告。
* *註銷 ONTAP 系統時保留備份*：現在，當您從 NetApp Backup and Recovery 註銷 ONTAP 系統時，您可以選擇捨棄先前備份的資料，或將其保留以供還原。NetApp Backup and Recovery 文件現在包含有關在系統註銷後使用 ONTAP CLI 還原保留資料的說明。


更多詳情請參閱 https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-backup-manage.html#unregister-netapp-backup-and-recovery-for-a-system["取消註冊系統的 Backup and Recovery"^]。

有關保護 ONTAP Volumes 工作負載的詳細資訊，請參閱 https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["了解使用 NetApp Backup and Recovery 的 ONTAP Volume 保護"^]。



==== Oracle 資料庫工作負載增強

在這個版本中，NetApp Backup and Recovery 針對 Oracle 資料庫工作負載引入了以下增強功能：

*還原到備用位置*：NetApp Backup and Recovery 現在支援將 Oracle 資料庫還原到備用位置（不同的註冊主機）。

有關保護 Oracle Database 工作負載的詳細資訊，請參閱 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-oracle-protect-overview.html["了解如何使用 NetApp Backup and Recovery 保護 Oracle 資料庫工作負載"^]。

[[cloud-volumes-ontap]]
=== Cloud Volumes ONTAP



==== Azure 中的 Cloud Volumes ONTAP 9.19.1

現在您可以使用 NetApp Console 在 Azure 中部署和管理 Cloud Volumes ONTAP 9.19.1 的正式版（GA）。

自 2026 年 8 月起，控制台已支援 AWS 和 Google Cloud 中的 Cloud Volumes ONTAP 9.19.1。

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Cloud Volumes ONTAP 9.19.1 版本說明"^]



==== 主機上的 Azure 加密，適用於 Cloud Volumes ONTAP

從 Cloud Volumes ONTAP 9.19.1 GA 版本開始，對於滿足先決條件的全新 Azure 單節點和高可用度（HA）部署，Azure 主機加密預設為啟用。此功能會在資料寫入和讀取主機時，對託管 VM 的實體伺服器上的資料（包括臨時磁碟和關聯的主機級快取）進行加密。

在 Azure 中部署 Cloud Volumes ONTAP 之前，請確認您的環境符合下列先決條件：

* 該 `EncryptionAtHost`功能已註冊到您的 Azure 訂閱。請參閱 https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Microsoft 文件：在主機上啟用加密"^]。
* 您選擇的 VM 執行個體類型支援在您的 Azure 區域中主機上的加密。請參閱 https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Microsoft 文件：尋找受支援的 VM 大小"^]。


請注意以下幾點：

* 無需額外組態。
* 如果這些先決條件未滿足，則不會為您的 Cloud Volumes ONTAP 部署啟用主機上的 Azure 加密。
* 主機加密僅適用於 Azure，不適用於 AWS 或 Google Cloud。


Microsoft 文件： https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["使用 Azure 入口網站透過主機加密啟用端對端加密"^]



==== Azure 和 Google Cloud 中的 Cloud Volumes ONTAP 叢集的後端網路加密

Cloud Volumes ONTAP 9.19.1 及更新版本支援 Azure 和 Google Cloud 中 HA 組態的後端叢集網路加密。

啟用叢集網路加密可能會影響叢集效能。請注意，並在啟用此功能前確認您的環境能夠容納額外的例行成本。

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["在 Cloud Volumes ONTAP 叢集上啟用後端網路加密"^]



==== 減少 Azure 排程維護期間中斷的能力

在排程維護期間，Azure 可能會短暫暫停 Cloud Volumes ONTAP HA 配對中的 VM。ONTAP 可能會將此暫停視為節點停電，並將儲存設備作業移至合作夥伴節點，然後在 VM 恢復時將其移回（接管與歸還）。即使沒有節點故障，此程序也可能毀損作用中的用戶端連線。

使用 Cloud Volumes ONTAP 9.19.1 及更新版本，您可以啟用選用設定，讓 HA 配對在 Azure 排程維護凍結期間繼續運作，而不會自動啟動接管與歸還。


NOTE: 此功能在 Cloud Volumes ONTAP 9.19.1 中以公開預覽版的形式提供。

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["防止 Azure 維護期間 Cloud Volumes ONTAP HA 配對發生中斷"^]

==== Hyper-V 工作負載增強功能

==== Kubernetes 工作負載增強功能

在此版本中、Kubernetes 工作負載引入了以下增強功能：

* *Trident Protect 26.08*：此版本包含 Trident Protect 26.08。
* *備份重試*：您現在可以在 Kubernetes 保護原則的進階設定中啟用備份重試，並設定重試次數和重試間隔。
* *部分備份成功*：您現在可以在 Kubernetes 保護原則中設定進階設定，以便在個別資源發生故障時繼續備份，從而使備份作業部分成功完成。這樣，即使某些資源在備份作業期間發生故障，您仍然可以還原已備份的資源。
* *損毀狀況一致與 VM 一致備份*：Backup and Recovery for NetApp Console 服務現在支援設定保護原則，以建立損毀狀況一致或 VM 一致的備份或快照。您還可以自訂在保護作業期間執行 VM 凍結的方式。
* *Console 代理程式 IP 位址變更時重新連接 Kubernetes 叢集*：Backup and Recovery for NetApp Console 服務現在可讓您在代理程式的 IP 位址變更時，將叢集重新連接至其 Console 代理程式。
* *將叢集移轉至新的 Console 代理程式*：Backup and Recovery for NetApp Console 服務現在可讓您在原始代理程式失敗或被刪除時，將叢集移轉至新的 Console 代理程式，以確保應用程式保護不中斷。


有關保護 Kubernetes 工作負載的詳細資訊，請參閱 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["了解如何使用 NetApp Backup and Recovery 保護 Kubernetes 工作負載"]。



==== Oracle 資料庫工作負載增強

在此版本中、Oracle Database 工作負載引進下列增強功能：

* *可插拔資料庫 (PDB) 還原*：現在可以還原單一可插拔資料庫 (PDB) 和 PDB 表空間，包括時間點恢復。
* *可插拔資料庫 (PDB) Clone*：現在可以將單一 PDB Clone 到現有的目標 Container 資料庫 （CDB） 中，並且可以選擇在 Clone 整個 Container 資料庫時排除 PDB。


有關保護 Oracle Database 工作負載的詳細資訊，請參閱 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-oracle-protect-overview.html["了解如何使用 NetApp Backup and Recovery 保護 Oracle 資料庫工作負載"]。
